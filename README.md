# KeeChest

Локальный менеджер паролей на Rust для компьютера и Android. Интерфейс в стиле
Fluent Design построен на [fluent_egui](https://github.com/georgebigscar-spec/fluent_egui).
Никаких облаков и аккаунтов: все пароли лежат в одном зашифрованном файле на
вашем устройстве.

## Возможности

- Хранилище в одном файле `.kchest`, зашифрованном ключом из мастер-пароля.
- Записи: название, логин, пароль, адрес, группа, заметки, избранное и
  произвольные поля (PIN, кодовое слово, коды восстановления); скрытые поля
  показываются маской и не участвуют в поиске.
- История паролей: при смене пароля старый сохраняется (последние 10).
- Поиск по названию, логину, адресу и группе; навигация по группам и избранному.
- Генератор паролей (длина, наборы символов, без похожих символов) и оценка
  надёжности через [zxcvbn](https://github.com/shssoichiro/zxcvbn-rs).
- Копирование в буфер обмена с автоочисткой (по умолчанию через 20 с) и
  пометкой для менеджеров буфера «не сохранять в истории».
- Автоблокировка после бездействия (по умолчанию 5 мин) и при сворачивании,
  блокировка вручную по Ctrl+L.
- Смена мастер-пароля и стоимости Argon2 с перешифровкой файла.
- Импорт из KeePass/KeePassXC (`.kdbx`, с паролем и ключевым файлом): группы,
  история паролей и дополнительные поля переносятся. Импорт CSV из
  KeePassXC, Bitwarden, Chrome, Firefox и других; экспорт в CSV (с
  предупреждением: файл не зашифрован, поля попадают в заметки).
- Светлая и тёмная темы.

Горячие клавиши: Ctrl+N новая запись, Ctrl+S сохранить в редакторе,
Esc отменить правку, Ctrl+L заблокировать.

## Запуск

```sh
cargo run --release -p keechest
```

Попробовать на готовых данных (мастер-пароль `demo-password`):

```sh
cargo run -p keechest-core --example demo_vault -- demo.kchest
cargo run --release -p keechest   # «Другое хранилище…» → demo.kchest
```

На Linux для окна нужны libxkbcommon-x11 и драйверы OpenGL/Vulkan, которые
обычно уже стоят в настольной системе.

## Готовые сборки

Workflow «Build» в GitHub Actions собирает программу для Linux (x86_64,
`.tar.gz`), Windows (x86_64, `.zip`) и Android (`.apk`, arm64 и x86_64) на
каждый пуш в `main` и каждый pull request; файлы лежат в артефактах прогона.
Тег вида `v0.2.0` дополнительно публикует их как релиз:

```sh
git tag v0.2.0 && git push origin v0.2.0
```

## Android

Тот же код собирается в приложение для Android 8.0 и новее
(`crates/keechest-android` и проект Gradle в `android/`). Что отличается от
версии для компьютера:

- Хранилища лежат в личной памяти приложения: другие приложения их не видят,
  разрешений на доступ к файлам не нужно. Резервная копия из облака и перенос
  на новое устройство отключены; сохраните копию сами: «Настройки →
  Сохранить резервную копию…». При удалении приложения хранилища удаляются
  вместе с ним.
- «Открыть существующее» и импорт KeePass/CSV используют системный выбор
  файлов; выбранное хранилище копируется в память приложения. Экспорт CSV и
  резервная копия сохраняются туда, куда укажете.
- Окно защищено `FLAG_SECURE`: без скриншотов, записи экрана и превью в
  списке недавних приложений.
- При уходе в фон хранилище блокируется (если включено «Блокировать при
  переходе в фон»), блокировка срабатывает до того, как экран снова
  покажется.
- Скопированное помечается как секретное (Android 13+ не показывает его в
  превью буфера), а очистка по таймеру срабатывает и в фоне.
- Клавиатура работает в режиме без подсказок и без обучения на вводе
  (`IME_FLAG_NO_PERSONALIZED_LEARNING`), для паролей — как поле пароля.
- На узком экране список и запись показываются по очереди, кнопка «Назад»
  закрывает диалог, редактор, запись, а затем сворачивает приложение.

Сборка (нужны Android SDK, NDK, JDK 17 и Gradle 8.9+):

```sh
rustup target add aarch64-linux-android x86_64-linux-android
cargo install cargo-ndk
cargo ndk -t arm64-v8a -t x86_64 --platform 26 \
    -o android/app/src/main/jniLibs build --release -p keechest-android
gradle -p android assembleRelease
# android/app/build/outputs/apk/release/app-release.apk
```

Готовый APK собирает GitHub Actions (см. «Готовые сборки» выше). Без ключа подписи APK подписан одноразовым отладочным
ключом сборщика, и следующая сборка не установится поверх: придётся удалить
приложение (сохраните резервную копию!). Чтобы обновления ставились поверх,
создайте свой ключ и добавьте секреты репозитория
`KEECHEST_KEYSTORE_BASE64` (файл `.jks` в base64), `KEECHEST_KEYSTORE_PASSWORD`,
`KEECHEST_KEY_ALIAS` и `KEECHEST_KEY_PASSWORD`:

```sh
keytool -genkeypair -v -keystore keechest.jks -alias keechest \
    -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 keechest.jks
```

Ограничения: нет автозаполнения в других приложениях, нет вставки из буфера
в поля (у egui нет контекстного меню). Набранный текст и скопированное
проходят через строки Java, которые нельзя затереть. Ключ и расшифрованные
данные остаются в памяти, пока приложение в фоне, до первого кадра после
возврата (тогда срабатывает блокировка) или до того, как система завершит
процесс. Стоимость Argon2 «Усиленная» (1 ГиБ) на телефоне может не
поместиться в память.

## Безопасность

| Что | Как |
| --- | --- |
| Ключ из мастер-пароля | Argon2id v1.3, по умолчанию 256 МиБ, 3 прохода, 4 потока; соль 32 байта, своя у каждого хранилища |
| Шифрование | XChaCha20-Poly1305, новый случайный 24-байтный nonce при каждом сохранении |
| Целостность | Весь заголовок (версия, параметры Argon2, соль, nonce) входит в AAD: подмена любого байта файла обнаруживается |
| Размер | Содержимое дополняется до кратного 1 КиБ, чтобы размер файла не выдавал число записей |
| Запись на диск | Временный файл с правами 0600, fsync, атомарное переименование; предыдущая версия остаётся в `*.kchest.bak` (тоже зашифрована; после смены мастер-пароля перешифровывается и она) |
| Память | Ключ, мастер-пароль и все поля записей затираются при освобождении (`zeroize`); буфер для JSON выделяется один раз нужного размера, чтобы открытый текст не оставался в старых аллокациях |
| Процесс | Отключены core dump; на Linux `PR_SET_DUMPABLE=0` не даёт другим процессам пользователя читать память через ptrace |
| Блокировка | Расшифрованные данные и ключ удаляются из памяти, состояние текстовых полей egui (в нём бывают копии введённого текста) сбрасывается |
| Защита от «бомб» | Параметры Argon2 из файла проверяются на разумные пределы до вычисления ключа |

Формат файла описан в [`crates/keechest-core/src/format.rs`](crates/keechest-core/src/format.rs).

Чего KeeChest не делает (пока): не защищает от вредоносной программы,
которая уже работает под вашим пользователем (кейлоггер, чтение экрана), и не
закрепляет память от выгрузки в swap. Поля ввода egui при редактировании
могут перевыделять строки, и старые буферы не затираются; эти копии живут
только до блокировки. То же касается промежуточных буферов библиотек
`keepass` и `csv` при импорте. Хранилище не рассчитано на одновременную работу из двух
запущенных копий программы.

Если забыть мастер-пароль, восстановить данные невозможно. Делайте резервные
копии файла `.kchest`: он зашифрован, его можно хранить где угодно.

## Устройство

| Путь | Что |
| --- | --- |
| `crates/keechest-core` | Формат файла, криптография, модель данных, генератор и оценка паролей. Без UI, с тестами. |
| `crates/keechest` | Приложение на eframe и fluent_egui. |
| `crates/keechest-android` | Библиотека `libkeechest_android.so`: вход для Android и обратные вызовы из Java. |
| `android/` | Проект Gradle: `MainActivity` (выбор файлов, буфер обмена, клавиатура), манифест, иконка. |

```sh
cargo test --workspace
```

Настройки (не секретные: последние файлы, тема, тайм-ауты, параметры
генератора) хранятся в `config.json` в каталоге настроек ОС, например
`~/.config/keechest/` на Linux.
